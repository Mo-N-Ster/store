## Implemented behavior inspected

- Bounded streaming `STORE_BACKUP_V1` ZIP with strict UTF-8 manifest, explicit DB/media entries, per-entry length and SHA-256 verification, duplicate/unexpected/path-traversal rejection, total input/expanded bounds, and extraction only into private staging. Hashes detect accidental corruption; they do not authenticate the archive.
- One `ActiveStoreOwner` coordinates Room operations and maintenance. An AtomicFile generation pointer and transition journal are resolved and the selected DB, foreign keys, and referenced product media are validated before repository operations.
- Backup checkpoints and closes the active DB, snapshots the database and referenced product images, validates the snapshot, writes/syncs a bounded archive, and publishes by same-filesystem rename. Automatic retention keeps seven `auto-*` archives and preserves manual archives.
- Restore extracts and verifies a private candidate, accepts only declared DB schema versions 1–3 (the current Room migrations are applied to the candidate copy), requires the current actor to remain an active Owner in that candidate, checks Room integrity/FKs/media, creates a pre-restore safety backup, then switches by PREPARED journal, AtomicFile pointer, post-switch checks, actor-attributed audit row, and COMPLETE journal. Invalid archive/candidate is rejected before the active pointer changes; a failed post-switch operation attempts rollback.
- Archive preview and restore compare the manifest schema marker with SQLite `user_version` over a read-only connection before Room can run candidate migrations. A focused native test verifies a validly hashed archive with a mismatched schema is rejected during both inspection and restore without changing the active generation.
- Reset requires an active Owner at the application boundary and current-password verification/confirmation in the authority, creates a verified safety backup and an empty validated generation, writes an actor-attributed reset audit before COMPLETE, and invalidates the in-memory session after success.
- Manual backup/export, archive inspection, restore, and reset are exposed in the Owner settings workflow through SAF ActivityResult contracts. URI streams are bounded and never converted to filesystem paths. The UI identifies backup sensitivity and reports provider durability as unverified.
- A unique daily WorkManager request is enqueued after Owner authentication with storage-not-low constraints; the Worker checks that a persistent Owner still exists. The WorkManager test confirms unique scheduling metadata, not actual after-restart execution or catch-up.
- Restore preview renders at most ten archive-entry details while retaining total entry count and an explicit truncation disclosure, avoiding a large eager Compose column for a bounded-but-large archive.
