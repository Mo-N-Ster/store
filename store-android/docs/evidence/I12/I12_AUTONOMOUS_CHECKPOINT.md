## Implemented in the current worktree

- `RecoveryArchive` is a bounded streaming ZIP codec with a strict UTF-8 manifest, application/schema version, exact allowlisted DB/media entry names, per-entry byte counts and SHA-256, duplicate/path/unexpected-entry rejection, compressed and expanded byte limits, entry/manifest bounds and a 120-second extraction deadline. Hashes detect accidental corruption; they do not authenticate an archive.
- `ActiveStoreOwner` now resolves a durable AtomicFile generation pointer and transition journal before the first Room read. One Room owner is held per generation; its coroutine gate serializes reads/writes with maintenance. Startup validates SQLite quick/full/FK integrity plus every referenced catalog image; an invalid prepared new generation falls back to the intact old generation or blocks safely.
- Manual backup snapshots a closed/checkpointed DB plus referenced catalog images into private staging, verifies the snapshot, writes and syncs an internal archive, then publishes it by same-filesystem rename. A bounded SAF stream copy records an actor-attributed export audit and reports external provider durability as unverified.
- Restore validates/extracts into private staging, requires the current Owner to remain active in the candidate, runs Room integrity checks on the candidate only, validates referenced images, makes a verified pre-restore backup, and switches generations through PREPARED journal + AtomicFile pointer + verification + COMPLETE. A committed restore audit is written into the new generation before COMPLETE; failure before commit retains the prior generation.
- Reset verifies an active Owner, creates and validates a fresh schema generation, creates the required safety backup, writes a committed actor-attributed reset audit into the empty generation, switches via the same journal/pointer protocol, and invalidates the in-memory session only after successful completion. The application authority verifies explicit confirmation and the current password through the existing lockout/audit mechanism.
- Recovery settings UI is Owner-only and supports SAF backup destination, archive inspection, explicit restore confirmation, and password-confirmed reset. Identity/session lock and the catalog media operation barrier span restore/reset; a successful switch clears session-bound UI state. A unique daily WorkManager job is enqueued after Owner authentication; only `auto-*` archives are pruned to seven, never manual safety archives.
